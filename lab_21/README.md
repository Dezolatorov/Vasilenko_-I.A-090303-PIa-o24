# LibraryAPI — система управления библиотекой

Итоговый проект (лабораторная работа №21): разработка, тестирование и развёртывание
прикладной Python-системы. Вариант 2 — «Библиотека».

## Назначение

REST API для управления библиотекой: читатели (Reader), авторы (Author), книги (Book)
и выдачи книг (Loan) с полным циклом «выдал — вернул».

## Функциональность

- Авторизация по JWT, две роли: `USER` и `ADMIN`;
- Каталог книг: просмотр, поиск, фильтрация, сортировка;
- Управление авторами и книгами (CRUD, только для ADMIN);
- Выдача и возврат книг с контролем бизнес-правил;
- Централизованная обработка ошибок, логирование, health check;
- Автодокументация API (Swagger).

## Архитектура

Монолит (уровень A) со слоями:

```
Client
  │
  ▼
API (FastAPI, api/)
  │
  ▼
Service (services/)   <─ бизнес-правила
  │
  ▼
Repository (repositories/)
  │
  ▼
SQLAlchemy (ORM)
  │
  ▼
SQLite (в проде заменяется на PostgreSQL через DATABASE_URL)
```

Структура каталога:

```
src/library/
├── api/            # HTTP-обработчики и routers
├── models.py       # ORM-модели
├── schemas.py      # Pydantic-схемы валидации
├── services/       # бизнес-логика
├── repositories/   # слой доступа к данным
├── exceptions.py   # доменные исключения
├── config.py       # настройки из окружения
├── auth.py         # JWT/пароли/зависимости
├── database.py     # движок и сессии SQLAlchemy
├── main.py         # создание приложения
└── seed.py         # наполнение БД демо-данными
```

## API (основные операции)

| Метод | Путь | Назначение | Доступ |
|-------|------|------------|--------|
| POST | /auth/register | Регистрация USER | публичный |
| POST | /auth/login | Вход, получение JWT | публичный |
| GET | /health | Проверка работоспособности | публичный |
| GET | /books | Каталог (поиск/фильтр/сортировка) | USER, ADMIN |
| POST | /books | Добавить книгу | ADMIN |
| GET | /books/{id} | Книга по id | USER, ADMIN |
| PUT | /books/{id} | Обновить книгу | ADMIN |
| DELETE | /books/{id} | Удалить книгу | ADMIN |
| GET | /authors | Список/поиск авторов | USER, ADMIN |
| POST/PUT/DELETE | /authors… | Управление авторами | ADMIN |
| POST | /loans | Выдать книгу | USER, ADMIN |
| POST | /loans/{id}/return | Вернуть книгу | USER(владелец), ADMIN |
| GET | /loans | Список выдач (фильтр) | USER(свои), ADMIN(все) |

Полная спецификация — в Swagger: `GET /swagger/openapi.json`.

## Бизнес-правила

1. Нельзя выдать книгу без свободных экземпляров (`available_copies <= 0`).
2. Нельзя выдать книгу читателю с просроченными выдачами.
3. Нельзя превысить лимит одновременных выдач (`MAX_ACTIVE_LOANS`, по умолчанию 5).
4. Вернуть можно только активную (не возвращённую) выдачу.
5. Дата возврата не раньше даты выдачи.
6. Нельзя удалить книгу, пока её экземпляры на руках; нельзя удалить автора с книгами.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| APP_NAME | LibraryAPI | Имя приложения |
| DATABASE_URL | sqlite:///./library.db | URL БД |
| SECRET_KEY | (dev-значение) | Секрет для подписи JWT |
| JWT_ALGORITHM | HS256 | Алгоритм JWT |
| ACCESS_TOKEN_EXPIRE_MINUTES | 120 | Срок жизни токена |
| MAX_ACTIVE_LOANS | 5 | Лимит выдач на читателя |
| LOAN_DAYS | 30 | Длительность выдачи |
| LOG_LEVEL | INFO | Уровень логирования |

Секреты не хранятся в Git — только в `.env.example` (заглушки) и `.env` (локально).

## CI

Pipeline (`.github/workflows/ci.yml`) на каждое изменение: install → lint → tests →
coverage (порог 70%) → заканчивается ошибкой при провале тестов/покрытия.

## Ограничения проекта

- БД — SQLite (файл) по умолчанию; PostgreSQL поддерживается через `DATABASE_URL`,
  но не развёрнут здесь (в среде нет сервера PostgreSQL).
- Кэш Redis и брокер сообщений не используются (уровень A, базовый).
- Пароли хэшируются стандартным хэшем PBKDF2-SHA256 (без bcrypt/passlib,
  их нет в окружении).
- CI декларативно описан; в текущем локальном окружении без Git-хостов
  фактический прогон pipeline не выполнялся.
- Миграции не используются — таблицы создаются автоматически (`create_all`).

## Демонстрационный сценарий

`tests/` содержат сквозной сценарий: регистрация → вход → добавление автора и книги
(ADMIN) → выдача книги (USER) → возврат → проверка каталога/фильтров.
