# Лабораторная работа №17 — Telegram-бот «Библиотека»

Асинхронный Telegram-бот на Python и **aiogram 3** для предметной области
«Библиотека» (вариант 2). Реализует каталог книг, поиск, выдачу и возврат,
CRUD, FSM-диалоги, Inline/Reply клавиатуры, собственный middleware и базу
данных SQLite с разделением на слои.

## Структура проекта

```
lab_17/
├── bot.py                    # точка входа: Bot, Dispatcher, polling
├── config.py                 # чтение настроек из переменных окружения
├── requirements.txt          # зависимости
├── pytest.ini                # конфигурация pytest (asyncio_mode=auto)
├── conftest.py               # pytest-фикстуры (временная БД на каждый тест)
│
├── handlers/                 # Telegram-обработчики (Router)
│   ├── start.py              #   /start, /help, /cancel
│   ├── menu.py               #   каталог, поиск, мои книги, возврат, CRUD, callback
│   └── registration.py       #   FSM: добавление книги, выдача книги
│
├── keyboards/
│   └── menu.py               # Reply Keyboard (главное меню) и Inline Keyboard
│
├── states/
│   └── book.py               # FSM-состояния (AddBook, BorrowBook)
│
├── services/
│   ├── library_service.py    # бизнес-логика и валидация
│   └── formatting.py         # форматирование текста ответов
│
├── database/
│   ├── db.py                 # aiosqlite: подключение и схема
│   ├── models.py             # доменные модели (Book, Author, Reader, Loan)
│   └── repository.py         # репозиторий — SQL-запросы
│
├── middlewares/
│   └── logging.py            # LoggingMiddleware (журналирование, счётчик)
│
└── tests/
    ├── test_library.py       # тесты бизнес-логики (CRUD, поиск, валидация, выдача)
    └── test_bot.py           # тесты Telegram-интерфейса (FSM, обработчики, middleware)
```

Архитектура соответствует методичке: `Dispatcher → Router → Handlers →
Services → Repository → Database`, бизнес-логика отделена от обработчиков.

## Установка

```bash
pip install -r requirements.txt
```

## Переменные окружения

| Переменная   | Описание                                                        | По умолчанию          |
|--------------|-----------------------------------------------------------------|-----------------------|
| `BOT_TOKEN`  | токен Telegram-бота (обязателен, НЕ хранить в коде)             | `""` (пусто)          |
| `ADMIN_IDS`  | id администраторов через запятую (резерв)                       | `""`                  |
| `DB_PATH`    | путь к файлу SQLite                                             | `./library.db`        |
| `LOAN_DAYS`  | срок выдачи книги в днях                                        | `14`                  |
| `SKIP_UPDATES` | пропускать накопленные обновления при старте (`1`/`0`)        | `1`                   |

Пример запуска:

```powershell
$env:BOT_TOKEN = "ваш_токен"
python bot.py
```

## Команды

- `/start` — показать главное меню (Reply Keyboard)
- `/help` — справка
- `/cancel` — отменить текущую FSM-операцию
- `/catalog` — список книг (каталог)
- `/search` — поиск книги (текст или `название|автор`)
- `/find <текст>` — быстрый поиск
- `/add_book` — добавить книгу (FSM)
- `/lend`, `/borrow <id>` — выдать книгу
- `/return` — вернуть книгу
- `/mybooks` — список выданных вам книг
- `/overdue` — просроченные выдачи
- `/edit_book id|название|автор|год|кол-во` — изменить книгу

Главное меню (Reply Keyboard) содержит пункты: «Каталог», «Поиск»,
«Добавить книгу», «Выдать книгу», «Мои книги», «Просроченные», «Помощь».

## Тестирование

```bash
python -m pytest
```

Минимум 10 тестов (фактически 29) — требования методички (п. 21). Тесты
покрывают CRUD, получение объекта, изменение, удаление, поиск, валидацию,
обработку некорректных данных, FSM-сценарий, бизнес-логику сервиса и
middleware.

## Примечание о среде выполнения (демонстрация без Telegram API)

В данной среде **реального Telegram API нет** (нет реального токена и сети
к `api.telegram.org`), поэтому приложение не может выйти в интернет.
Проверка выполнена локально и офлайн:

- **Тесты** (`python -m pytest`) — 29 тестов проходят без сети: бизнес-логика
  тестируется на временной SQLite, обработчики вызываются напрямую с
  mock-объектами `Message`/`CallbackQuery` и `MemoryStorage`.
- **Демо-сценарий** (`python demo_offline.py`) — запускает сборку приложения
  (`build_dispatcher`, `bot.py`), регистрирует middleware и проверяет цепочку
  «/start → каталог → поиск → FSM добавления → выдача → мои книги → возврат →
  просроченные» через прямые вызовы обработчиков с mock-объектами.

Для реального запуска достаточно задать `BOT_TOKEN` и выполнить `python bot.py`
при доступной сети к Telegram Bot API.
